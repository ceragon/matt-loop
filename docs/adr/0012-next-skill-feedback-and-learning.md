# next_skill 机械反馈＋space 隔离在线 few-shot

> 2026-11-25，#48 第二阶段。第一阶段「`next_skill` 字段瘦身＋预测可见性」见 ADR-0008；本 ADR 记录反馈、近期序列、持久学习与隐私边界。两阶段同属 #48，阶段一完成不关票。

## 背景

原 `next_command` 预测没有反馈机制，脚本不知道预测是否被采用，也不会随历史纠正改进。对本机 `$TMPDIR/loop` 旧数据做只读粗对齐时，仅得到 14 对可比较样本：2 对完整一致、2 对同 skill 不同参数、10 对偏离。该样本小且口径已过时，只证明反馈机制有设计价值，不作为正式基线，也不自动回填。

现有运行产物默认位于 `$TMPDIR/loop`，会随 OS 清理；`next_skill` 需要独立的持久学习存储才能跨重启积累。学习仍复用每轮既有抽取调用，不新增模型请求；脚本只做机械收集、对齐、统计和限量选取，模型只做语义预测。

## 决定

### 1. 纯机械反馈

1. **事实源与配对**：用户实际放行的下一轮主任务首个非空行是唯一 ground truth。按调用方传入的 `target` 字面值分组，以同 target 下一次实际完成发送的主任务结算上一轮预测；`target_address` 不作长期键，跨 target 不互判。
2. **发送边界**：发送前预检失败不消耗待观察预测；主任务发送成功后立即结算，后续抽取失败仍保留反馈并附在 error JSON 的增量字段中。本轮抽取失败没有新预测，不创建新待观察记录。
3. **实际类型**：首个非空行只用于机械解析 skill。候选七项、集外斜杠命令、普通文本均是合法实际结果；重置与切模型前置不算实际 `next_skill`。
4. **待观察**：每轮成功抽取都创建待观察记录，包括 `next_skill=""`。尚未出现下一次实际放行不算偏离；同 target 异常出现多条未结算记录时只对齐最近一条，旧记录标 `orphaned`。
5. **无参数判分**：只比较预测 skill 与实际 skill，不保存或评估实际参数。学习案例与 `next_skill_feedback` 只保留解析后的 `actual_skill`／实际类型，不持久化实际首行全文。

### 2. 指标与呈报

- **skill 命中率**＝预测 skill 等于实际 skill 的样本数 ÷ 实际属于七项的已结算样本数；空预测与无效预测均计未命中。
- **预测覆盖率**＝合法非空预测数 ÷ 实际属于七项的已结算样本数。
- **空预测正确率**＝合法空预测数 ÷ 实际为普通文本、集外 skill 或无斜杠的已结算样本数；无效预测不算正确弃答。
- 另报 `invalid_prediction` 数量与全部样本数，避免闭集格式错误被空预测指标掩盖。
- 统计同时提供全量、最近 20 条滚动窗口（恒带样本数）以及 `examples_used=0`／`examples_used>0` 两队列；`examples_used` 专指 few-shot 条数，近期序列使用情况另记。
- 对比只用于观察趋势，不宣称严格因果提升；首版验收不设必须提升多少个百分点的门槛。
- `next_skill_feedback` 携带上轮预测、本轮实际 skill／类型、机械判定与上轮放行 id，随正常 result 或发送后的 error JSON 返回，沿用现有 webhook。调用方选项卡呈报关键变化；案例正文绝不进入 result/webhook。

### 3. 近期实际 skill 序列

1. 主任务发送成功后立即记录事件，抽取失败不丢。范围为**同 space id＋同 target**，最多最近 8 个主任务，包含本轮，按 oldest → newest 排列。
2. 只记录首行解析出的 skill 名；集外斜杠命令也记名，普通文本只记 `plain_text`，不记参数或任务正文。重置、切模型等前置不进入序列。
3. 跨 space 不共享序列。候选预测仍固定七项，记录集外命令只为表达链路位置，不自动扩集。
4. 当前预测优先级为：**当前回复明示＞当前近期序列＞few-shot 历史示例＞输出 `""`**。序列不足以判断时不为覆盖率硬猜。

### 4. 学习案例与 few-shot

1. 每条学习案例保存：`target`、`space_id`、预测轮／实际轮放行 id、时间、机械分类、预测轮干净回复全文、当时 `next_skill`、解析后的 `actual_skill`／实际类型，以及当时最多 8 条的近期序列快照。整屏原料与下一轮完整放行正文不入案例。
2. 每轮最多机械选取 4 条同 space 案例：优先最近纠错，补足命中与正确弃答；同 space 内同 target 优先，再按时间倒序。不做向量检索，不调模型挑案例。
3. 注入形态为「历史近期序列＋历史干净回复＋当时预测＋实际 skill」。历史干净回复总预算 16,000 字符，超限少选，不截断单条正文；近期序列是紧凑元数据，不占该预算。无历史时完全沿用原 prompt，冷启动行为不变。
4. 命中、纠错、正确弃答均可成为案例。few-shot 只提供历史映射示例，不覆盖当前回复或当前近期序列。
5. 同 target 跨 space 仍按 target 结算机械反馈，但相关案例标 `learning_excluded:"space_changed"`，不进入任何 few-shot 池；旧 space 的干净回复不得随新 space 的抽取请求出机。

### 5. 持久存储与隐私

1. 默认目录为 `${XDG_DATA_HOME:-~/.local/share}/matt-loop/learning/`，可用 `LOOP_LEARNING_DIR` 覆盖。目录权限 `0700`、文件 `0600`；公开仓库只放占位符测试夹具，真实回复、真实标识符与机器路径不入库。
2. 学习数据采用本地 JSONL/JSON。保留期限为 90 天且每 space 最近 100 条，到期或超额先删最旧；待观察记录同受约束。只含计数的全局汇总可长期保留，删案例正文不回删累计统计。清理由正常读写触发，不加后台守护进程。
3. 本地文件的读改写使用短临界区锁，锁绝不跨抽取 API/pi 调用；以预测轮与实际轮放行 id 去重，统计原子写入。锁失败、超时、权限错误、I/O 错误或记录损坏均降级为 `learning_warning`，不新增 error kind、不改退出码、不阻断主轮。
4. 使用 api 后端时，允许同 space 历史干净回复随既有抽取请求发往 `LOOP_API_BASE`；pi 按 pi 自身配置处理。只发送本 ADR 定义的案例内容，不跨 space，不新增调用。
5. `LOOP_LEARNING=off` 时不读写持久学习记录、不记录或注入近期序列、不注入 few-shot；现有 `next_skill` 预测、抽取与发送照旧。其他值默认开启。
6. 不自动回填旧 `$TMPDIR` 数据；正式统计从第二阶段上线后开始积累，旧运行产物仍按原生命周期自然清理。

## 被否方案

- **模型语义复判／独立 judge**：只把评价尺子做复杂，不直接改善 few-shot；纯机械判分客观、可复算、零新增成本。独立 judge 若使用不同模型还需要第二次调用，与零新增调用约束冲突。
- **完整指令与参数学习**：预测器缺少调用方完整上下文，历史标识符可能陈旧；由 ADR-0008 改为纯 skill 预测后整片作废。
- **跨 space 案例池**：起效更快但会把一个项目的历史正文带入另一个项目的抽取请求；改以 space id 隔离。space 删除重建得到新 id 时视为新池，即使 name/folder 相同也不自动继承。
- **以 name/folder 作案例池键**：name 可撞名，folder 明确可由多个 space 共用；只有解析后的 space id 无歧义。id 缺失时禁用该轮学习并返回 `learning_warning`。
- **只统计不反哺**：能度量但不能让预测随纠正改善，不满足 #48 的学习目标。
- **训练权重／自动改仓库 prompt**：复杂度与失控面过高；采用本地、限量、可关闭的在线 few-shot。
- **自动扩候选 skill**：历史中的集外命令只作链路位置上下文，扩集仍是单独明确决策。
- **pre-send 机械闸**：反馈与学习均不改变 ADR-0008 的建议性发送边界。
- **自动回填旧数据**：旧数据不完整且口径不同，导入会污染正式指标并重新持久化旧回复。

## 后果

- 学习数据获得独立于 `$TMPDIR` 的生命周期；删除或重建 space 会产生新案例池和一次冷启动，这是隔离优先的已知代价。
- api 后端会把选中的同 space 历史干净回复再次发送给当前抽取端点；这是在线 few-shot 的必要代价，由 `LOOP_LEARNING=off` 提供总开关。
- 机械指标可复算，但近期窗口与有无 few-shot 的对比只显示相关性，不能单独证明学习导致准确率提升。
- 学习链路全部建议性，任何存储或锁故障都不能连累正常发送、抽取与结果交付。
- #48 分两批交付：阶段一完成仅实现可见性，不关票；阶段二的反馈、统计、近期序列与 few-shot 全部落地后才具备关票条件。
