# 会话命名约定：一 bot 一机器恒一条 `<bot>-<machine>`，任务区分靠显示名

## 背景

issue #62：调用方按任务给目标会话起名，同一 bot 实例在同一机器上累积出多条命名
会话。get-or-create（ADR-0009）只按 `--target` 字面值命中，没有「按 bot 扫既有
会话」的逻辑；每换一个任务长出一条新 tab，谁在跑什么只能人肉辨认。SKILL.md 自身
两套约定矛盾：会话名推荐 `<kind>-<repo>`（一仓库一条），显示名推荐
`<bot 族>_<任务描述>`（一任务一条），调用方实际按任务起名。

议题演化：原案 `<bot>-<repo>`（一 bot 一仓库一条）→ grill Q6 裁定 repo 也不进
名字（一条会话跨所有仓库、所有 kind）→ 终态 `<bot>-<machine>`（一 bot 一机器恒
一条）。grill Q1–Q14 全部拍板（2026-11-25）：同实例同机串行由调用方保证，并行
只发生在实例之间；任务区分全部交给显示名每轮覆盖。

事实核查（grill 2026-11-25 探针＋当时代码核对，位置按函数级描述）：

1. 名字按机器解析、两机不共享：本机 `hc get` 远端会话名报 not_found，须
   `machine/tN` 跨机寻址；故 machine slug 进名字只为同机唯一与人类可读，不承担
   跨机路由。
2. `hc` 无 rename 子命令：存量会话不能改名，只能自然结束或 kill 重建。
3. `--cwd` 仅创建时生效：只有 `hc run` 消费 `--cwd`（dispatch.py 里拼装创建命令
   消费 `--cwd` 的那处）；复活分支不 run、沿用终端原 cwd；复用轮传了 `--cwd`
   不改工作目录。
4. `--rebuild` 仅 `session_occupied` 占位分支生效（dispatch.py 里 `--rebuild`
   的分流判定处），其余分流误传 `bad_args`；同 kind idle 的既有会话没有 rebuild
   可用。
5. pane 已在 adopt 提前返回（dispatch.py 的 adopt 预检处），无跨空间挪 pane API
   （ADR-0011 背景 3）：常驻空间约定靠每轮恒传同一 `--space` 值承重，pane 落地
   后不挪。
6. 学习 space id 取请求 `--space` 解析值（dispatch.py 的
   `resolve_space_id_for_learning`）：一 bot 一常驻空间即一案例池；跨任务复用同
   target 会混任务序列（见决定 8）。

现状实证：调用方实际按任务维命名，同族并行两条会话属不同实例（实例 slug 不同），
不是同实例违约并行。

## 决定

（grill Q1–Q14 裁定，2026-11-25；纯约定＋文档，零 dispatch.py 改动、零新 error
kind、零 result 字段变更、零退出码变更。）

1. **形态与 slug 纪律**：会话名定形 `<bot>-<machine>`。bot＝派发实例 slug（族名
   只留显示名前缀；同族副本实例 slug 不同，各占一条）；machine＝本机恒 `local`，
   远端＝该机器上的调用方本地取值（该机 herdr 机器名或该机配置）——文档只写规则、
   不写死任何远端名。来源写死调用方配置（DS Bot 用 bot 名；Grok Bot 用账号/配置
   名＋角色）。脚本零映射、只校验 1–32 位 `a-z0-9-_`、不校验式样；超长调用方自截、
   保证同机唯一。（**本条形态段＋来源句 superseded by ADR-0025**：会话名＝人工
   指派的成品字面量，不再规定 `<bot>-<machine>` 结构；字面量全局唯一、永不改，
   写进调用方恒加载配置、每轮照抄、禁现场拼装；bot 名可改可重名不再作来源。
   脚本零映射、1–32 位校验不变。）
2. **恒一条与串行**：一 bot 一机器恒一条，跨仓库、跨 kind。同实例同机串行是调用方
   保证；违约并行撞 `not_idle` 是既有机械兜底，不新增闸。
3. **显示名每轮覆盖**：任务区分＝显示名每轮覆盖。同任务各轮同名（幂等），新任务才
   换名；放行卡每轮贴显示名。手工改名确认保留 best-effort、每轮触发（ADR-0010
   决定 5 不变）。脚本「新鲜路径必传、复用轮可选」机制不变。代价：新任务覆盖 tab
   名后旧任务在 GUI 无痕、只剩终端历史（如实接受）。
4. **cwd 纪律**：`--cwd` 仅创建生效、复活沿用终端原 cwd、复用轮传了不改工作目录
   （机械事实，见背景 3）。跨仓库任务提示词恒带目标仓库绝对路径，执行者跨目录干活。
   常驻仓库真的变更时：用户显式关 tab（或授权 kill）→ finished → 下轮 get-or-create
   带新 `--cwd` 重建；同 kind idle 时没有 `--rebuild` 可用（背景 4）。
5. **常驻空间**：一 bot 一常驻空间（调用方配置的固定 `--space` 值），每轮恒传同一
   值；pane 已在提前返回、无跨空间挪 pane API 是承重机械事实（背景 5）。落点与请求
   恒一致。
6. **kind 切换＝同名强制重建**：约定内换 kind＝同名 `--rebuild`，经用户显式授权、
   只杀 idle/done 占位者；`--expect-proc` 同步改新 kind。换 `--target` 到另一命名
   会话降为约定外逃生门（get-or-create 机制仍在，旧会话保留可切回）。
7. **重置常态＋延伸纪律**：新任务首轮一律推荐 `--reset` 前置（不限会话起始 skill），
   避免旧任务上下文渗进新任务。这是建议不是闸：ADR-0004 的机械拒发范围不变（仍只兜
   行首起始 skill＋turn>0＋none），普通任务新任务首轮不重置不被拒发。
8. **学习污染接受**：同 target 跨任务复用后，近期序列与案例池混任务（背景 6）——
   已接受代价。调用方纪律：新任务首轮放行卡标「已编辑：新任务，上轮预测不适用」
   （预测可见性四状态现成，ADR-0008）。不改配对键、不部署 `LOOP_LEARNING=off`
   （零代码约束）。
9. **存量不迁移**：`hc` 无 rename（背景 2）；旧名会话 get-or-create 到自然结束，
   旧 idle tab 用户手动关，不为改名杀在跑的工作。
10. **词汇**：GLOSSARY 会话名/显示名条目更新；新增「新任务（New Task）」（调用方
    判定任务意图切换后的首轮；触发换显示名＋推荐重置＋预测标注三件套；同任务多轮
    不算）与「常驻空间（Home Space）」（调用方为 bot 配置的固定 `--space` 值，
    会话 pane 永久落点）。

## Considered Options

- **任务维命名（现状）**：每任务一条会话。否——Q1 同实例同机串行保证下，任务区分
  交给显示名即可；多条会话累积、人肉辨认。
- **`<bot>-<repo>` 原案**：一 bot 一仓库一条。被 Q6 取代——repo 也不进名字，一条
  会话跨仓库跨 kind。
- **不嵌机器（助手推荐，用户否）**：`<bot>` 单 slug。用户裁定接受冗余——machine
  slug 保同机唯一与人类可读，远端只写规则不写死（Q14 修正：绝不写死任何远端名）。
- **逐轮换 space**：否——静默漂移，拆散既有组织；一 bot 一常驻空间每轮恒传。
- **`LOOP_LEARNING=off` 防污染**：否——零代码约束，且关掉学习损失预测；接受污染＋
  调用方标注。
- **主动迁移存量**：否——hc 无 rename，为改名 kill 重建违背「绝不杀在跑工作」。
- **改学习配对键**：排除——零代码约束。
- **会话名式样机械校验**：否——约定是推荐不是闸，脚本只校验 1–32 位 a-z0-9-_。

## Consequences

- 调用方配置三固定项：bot slug、machine slug 规则（本机 local／远端本地取值）、
  常驻空间。（**此句经 ADR-0025 修订**：固定项变为两项——成品会话名字面量、
  常驻空间；machine slug 规则退役。）名字漂移不会静默另建会话（get-or-create
  按字面值命中）。
- 约定无机械强制，靠调用方读新 SKILL.md 生效；部署副本落后是已知风险面（先例：
  副本曾停在 #34/#35 之前，把发送上限误载为「两次」），四份运行副本同步属部署侧
  （#64），不在本 ADR 实现范围。
- 已接受的代价：跨仓库项目上下文错配（执行者加载创建仓库的 CLAUDE.md）；学习
  序列/案例池混任务；旧任务 GUI 无痕、只剩终端历史；`--cwd` 复用轮无效。
- 零 dispatch.py 改动、零新 error kind、零 result 字段变更、零退出码变更；违约
  机械兜底（not_idle、session_occupied、reset_required）全部沿用既有。
- 隐私：公开仓库不出现真实机器名、hostname、用户名、绝对路径；远端机器只写规则；
  实证泛化（沿用 ADR-0010 先例）。
