# 实施切片与迁移护栏顺序：快照先于网关，重构片串行，棘轮自检

## 背景

地图 #71 的三张主干设计票已全部定型：ADR-0016（测试缝：`Deps` 注入加命令级
`FakeHerdr`）、ADR-0018（herdr 领域网关：封装命令字面量、seam 不动）、ADR-0020（一轮
管线：`run(request, deps) → Outcome`、直线阶段加 `RunState`）。三份 ADR 都把同一件事
留了下来：

- ADR-0016 决定 10：「怎么把这些步骤切成实施票，等三张设计票都定型后再定」。
- ADR-0018 Consequences：「实施切片与护栏顺序要等一轮管线票定型后才能写具体」。
- ADR-0020 决定 14：特征化快照是抽管线的硬前置，「具体怎么切成实施票不在本 ADR」。

本 ADR 关闭这个悬案。它只载**决定**（顺序、护栏机制、更新规则）；每片的标题、范围、
验收细节随 #82 的决议评论发布，不进 ADR，因为那是易变的计划，不是难回退的取舍。

事实基线：

1. 现有 25 个测试文件约 5500 行，CI 在 `loop/scripts` 里一个文件一个进程地跑；测试里
   `dispatch.<名> =` 赋值约 86 处。
2. `dispatch.py` 约 2400 行，三张设计票的改动几乎全落在这一个文件上。
3. 折叠判据修复（ADR-0019）已合入 main，`readback` 阶段的迁移基线就是它之后的 main。
4. 部署单元是 `loop/scripts/` 整目录；README 仍写「一个 Python 脚本」，而本轮会新增
   `errors.py`、`turn.py`、`herdr.py`、`pipeline.py` 四个兄弟模块（`learning.py` 已有
   先例）。

## 决定

（grill 裁定，2026-11-25；纯内部结构与测试层，零外部契约变更——flag、error kind、
`result.json`、`notify.json` 形状与 ADR-0001…0020 均不动。）

1. **切片与依赖图**（代号在 #82 决议评论里逐片展开）：
   - 测试侧：`T1` 纯搬家到 `tests/`；`T2` 引入 `Deps`；`T3` 纯新增 `FakeHerdr` /
     `harness.run` / `fixtures/` / 契约一致性检查 / 解析测试 / 故障键守卫（依赖 T1、
     T2）；`T4` 迁三个供应方文件并立测试侧棘轮（依赖 T3）；`T5` 其余消费方按文件分批迁
     （依赖 T4）；`S` 特征化快照（依赖 T4）；`R` 收尾（依赖 T5、G3）。
   - 重构侧：`A` 迁出 `errors.py` 与 `turn.py`（无依赖）；`G1` 纯新增 `herdr.py`
     （依赖 T3、A）；`G2` 迁会话簇、`G3` 迁空间簇（依赖 G1、S）；`P1` 纯函数先行
     （依赖 G3、S，以及地图外的 `parse_space` 实施票）；`P2` 新建 `pipeline.py` 并把
     `main` 体整体搬入 `run`、顺带堵 ⑤ 的两处洞；`P3` 按 15 阶段拆 `run`（2–3 片）；
     `P4` 抽 `poll` 与 `guard`。
   - 每片独立合入且全绿；`T1` 与 `T2` 互不依赖，可并行。
2. **特征化快照排在网关迁移之前**，不只是抽管线之前。ADR-0020 决定 14 只把它定为抽管线
   的前置；但网关要改写约 35 个调用点，且带五处含义各异的 `NotFound`、「`find_app_bin`
   先求值保住 `missing_tool`」这类次序契约，同样需要快照护栏。快照只覆盖五路分流的成功
   路径与关键故障点；网关自己的行为（焦点还原、`keep` 落地轮询、`send` 补发、赠送 shell
   清理）归 G1 的 interface 测试，不进快照。
3. **改 `dispatch.py` 的重构片串行**：同一时间只许一个在途，次序 `A → G2 → G3 → P1 →
   P2 → P3 → P4`；会话簇先于空间簇，因为 `adopt` 迁移风险最大，应让快照先吃过一轮较小的
   迁移。测试侧各片与 `G1`、`S`、`R` 不改 `dispatch.py` 行为，可与重构片并行。
4. **棘轮守卫自检式**：两道棘轮（`tests/` 内不得 monkeypatch `dispatch.<名>` 或写
   `os.environ[...]`；`dispatch.py` 不得出现 herdr 命令字面量）各是 `tests/` 里一个普通
   测试文件，白名单是文件内的字面量列表，随 CI 运行。「只许缩小」靠自检保证：白名单里
   某条已不再违规时，守卫自己失败，逼 PR 把它删掉。终态白名单为空时删掉常量，守卫变成
   无条件断言。测试侧棘轮立在 T4，命令字面量棘轮立在 G1。
5. **快照基线与更新规则**：基线在 S 合入时冻结，取 ADR-0019 之后的 main。此后分两种：
   重构片（网关、管线各片）快照 diff 必须为空，不许更新；行为性 bugfix 可在同一 PR 里
   更新快照，但 PR 须显式列出 diff 并写明「有意的契约变化」。S 合入前合入的 bugfix 自然
   进入基线。
6. **兼容别名与旧桩的退役放在收尾片 `R`**，依赖 T5 与 G3，不等管线：`HcFailure` /
   `AppFailure` 与旧桩类只被测试侧引用（ADR-0018 Consequences）。`R` 做三件事：删旧桩类
   与跨文件 import、删别名、两道棘轮白名单清空。
7. **部署单元整目录，加部署冒烟门**：通用验收门里加一条——把 `loop/` 整目录拷到临时
   位置，在那里跑 `dispatch.py --help` 必须成功，使漏拷兄弟模块在 CI 里红，而不是到副本
   上才发现。`A`、`G1`、`P2` 这三片新增兄弟模块，尤其依赖它。`A` 顺手把 README 的
   「一个 Python 脚本」改为 `loop/scripts/` 整目录，并在片的验收里写明「副本须整目录
   同步」。
8. **通用验收门**（每片都过，各片只列增量）：全部测试文件逐个跑绿；卫生扫描 clean；两道
   棘轮白名单只缩不增；外部契约零 diff（flag、error kind、`result.json` 与 `notify.json`
   形状、台账内容与写入时序）；`S` 之后快照 diff 为空；部署冒烟。
9. **地图外与挂接点**：
   - `--space` 三态解析的纯函数实施票先独立交付、不进本清单；`P1` 的 `plan_space` 在
     `parse_space` 之上薄包装（只把结果映射成 reuse / create / 错误，不重写匹配规则），故
     `P1` 依赖它。
   - `space.new` 真实返回的脱敏样例是独立的 HITL 小票，不挂依赖、不阻塞任何一片；样例
     到手后另提一个只加 fixtures 与一条解析测试的小 PR，采不到不影响终态（ADR-0018
     决定 13b）。
   - ④（台账 journal）挂在 `P2` 之后，只换 `RunState` 三个方法的方法体；⑤（学习
     session）挂在 `P3` 之后，因为 `state.learning` 的四个调用点要阶段拆出来才存在。二者
     都不阻塞管线各片；其设计票定型后若需增删片，回头追加到切片清单。
   - 补记（ADR-0022，#83）：④ 已定型——落地片仍挂在 `P2` 之后，只换 `RunState` 三个方法
     的方法体，并新增兄弟模块 `journal.py`（过部署冒烟门）；该片 PR 须列出约 5 处延后落盘
     改为立即落盘的快照 diff（决定 5 的「有意的契约变化」）。`S` 片的快照须带「`FakeHerdr`
     每收一条命令读一次磁盘台账并记下」，以照出「先记账后发送」的次序。

## 与既有 ADR 的关系

- **ADR-0016**：决定 10 的迁移步骤即 T1 → T2 → T3 → T4 → T5 与 R；棘轮守卫的机制在此
  补全（决定 4）。
- **ADR-0018**：网关实施分 G1（纯新增）、G2、G3；兼容别名退役位置在决定 6。
- **ADR-0020**：决定 14 的快照前置不变，本 ADR 把它提前到网关迁移之前（决定 2）；
  15 阶段的拆分落在 P3，`pipeline.py` 的创建落在 P2。

## Considered Options

- **快照只排在抽管线之前**（ADR-0020 的最低要求）：否——网关迁移同样触碰次序契约，无
  快照护栏则要等到管线才第一次发现回归，代价是多一片。
- **重构片并行**：否——同改一个两千多行文件，冲突成本高于并行收益。
- **棘轮用 git 基线对比**：否——需要在测试里取 base 引用，环境依赖重；白名单自检式不依赖
  任何 git 状态。
- **别名与旧桩退役等管线之后**：否——它们只被测试侧引用，与管线无关，早退役早减负担。
- **现在就建实施票并挂原生 blocked-by**：否——wayfinder 只规划；依赖边先写在清单里，
  由后续 `/to-spec`、`/to-tickets` 落成原生依赖。
- **新增 GLOSSARY 词条**（棘轮守卫、特征化快照、切片）：否——它们是测试工程与实施过程
  词汇，ADR-0016 / 0018 / 0020 一直就地使用而不入词表；GLOSSARY 只收 loop 领域词。

## Consequences

- 快照会比 ADR-0020 要求的更早，约多一片；换来网关迁移期间的回归护栏。
- 串行规则牺牲重构侧的并行度；测试侧可并行，部分抵消。
- ④⑤ 的设计票定型时可能增删片；清单是活的，本 ADR 只固定顺序与护栏原则。
- 每个新增兄弟模块的片都要过部署冒烟；副本同步由使用者整目录进行。
- 隐私：切片清单与样例同样遵守公开仓库红线（占位符、不含本机路径、用户名、主机名、
  真实会话标题或 token）。
