# next_command＝抽取顺便做的下一步完整指令预测

## 背景

PAW 系调用方有时把该走 skill 的活用纯文本直令发进执行者会话（实证：
`pop-dwwn.1-build-r1`「照方案开工：…写 prototype-guide.html」是 prototype 活
却没走 `/prototype`；`pop-pmif-pushmr`「发令：push…开正式 MR」也无 skill 形式）。
台账 120 条放行里 82 条纯文本开头；既有机械闸门只覆盖「会话起始 skill 斜杠
形式＋重置纪律」（ADR-0004），纯文本直令同时绕过 skill 触发与重置纪律。用户
要求通过 loop skill 反向约束调用方输入，并明确开了「决策模型判定输入合法性」
的口子。注意区分：此前被否的是「/ask-matt 决策模型判意图」（工作流路由，收益
不高）；本次是输入合法性信号，目的不同。

事实核查（2026-11-23）：抽取后端（默认直连 API，ADR-0005）每轮已读整屏原文，
执行者回复经常明示下一步（「共识稿已出，建议 /to-spec」）；从回复预测下一步
比从孤立输入猜「该不该走 skill」上下文更富。dispatch 以 `EXTRACT_FIELDS`
白名单投影抽取 dict 进 result（`**ext`），加字段即自动进 result/台账/webhook。

## 决定

复用抽取的同一次 API 调用，抽取完成后顺便输出 `next_command` 预测字段
（用户提案：零新增 API 调用、不碰发送路径）。

1. **字段**：`next_command`（字符串）＝调用方下一轮该发的**完整斜杠指令**
   （含参数，参数从原文上下文取，如 `/implement pop-xxxx.1`）；`""`＝无预测
   （下一步是用户答复、自由操作、或看不出）。候选集为七个打法 skill：
   `wayfinder`、`grill-with-docs`、`to-spec`、`to-tickets`、`implement`、
   `implement-spec`、`prototype`。用户原提案为前四个；扩到七个使
   to-tickets→implement 交接不失语，起始 skill 已有机械纪律兜底、预测只帮
   调用方提前备 `--reset`。
2. **唯一推测字段**：extract.md「只依据原文，不推测」规则为它开显式例外；
   其余字段逐字纪律一字不动。`next_command` 豁免原文子串校验（与
   `needs_user` 同待遇），不进 `rewritten`；参数仍须取自原文，不得发明新
   标识符。
3. **宽容投影**：缺失或非字符串按 `""`，不整轮报错——建议性字段不连累整轮
   （与 webhook 失败不连累整轮同哲学）。结构校验（形状门）不检查它。
4. **建议不是闸**：不碰发送路径、无新 error kind、不拒发。反向约束落在
   SKILL 纪律：判读结果时把预测呈给用户；同 target 下一轮放行**应照用预测
   指令作开场行**（可编辑，偏离须向用户明示理由）；预测是会话起始 skill 且
   `turn > 0` 时，同次放行一并推荐 `--reset`（既有纪律，ADR-0004）。
5. **两后端同生效**：api/pi 共用 extract.md；两处「六个字段」指令同步。

## 被否方案

- **发送前识别闸（pre-send）**：每条模糊输入发送前调模型判「该不该映射成
  skill」。拦得住当下违规，但每轮多一次 API 调用、发送路径多一个故障面，
  且从孤立输入判断比从回复预测更难、误拦风险高。被否（用户选预测）。
- **纯机械关键词表**：脚本维护「开工词表」做语义判断，越「脚本做机械、
  模型做语义」边界（ADR-0002）；词表维护不尽、误伤正常中途指令。被否。
- **纯文字纪律（现状）**：SKILL 写规则靠调用方自查——PAW 已证明不完全
  遵守，用户要的是反向约束不是又一段提醒。被否。
- **裸 skill 名＋依据引文＋置信度**：用户要「直接给出完整指令」，调用方
  零组装；依据/置信度在「调用方反正要审放行全文」的前提下收益低，且置信度
  不可机械校验、与抽取纪律相悖。被否（单字段 `next_command`）。
- **预测＋偏离机械警告**：下一轮输入与上轮预测不符时台账标警告。多一层
  跨轮状态与机械，约束仍靠自觉；缓议——PAW 若不理预测，升级路径是复活
  pre-send 闸（预测字段届时成为它的上下文输入）。

## 后果

- 结果契约加第六字段；PAW 系/Grok Bot/DS Bot 在 result/台账/webhook 同一份
  JSON 里看到 `next_command`。旧调用方不读它也不受影响（纯增量）。
- 抽取器角色从「纯抽取」扩为「抽取＋一个推测」；边界由 extract.md 显式例外
  与本 ADR 钉死，防日后被当 bug 改回去。
- 预测质量依赖执行者回复明示下一步；ask-matt 打法链高度线性
  （grill→to-spec→to-tickets→implement），多数交接点可预测。参数可能猜错，
  放行闸（用户审全文）兜底。
- 本轮纯文本直令仍发得出去——预测约束的是**下一轮**；这是软约束的已知局限，
  升级路径见被否方案末条。
