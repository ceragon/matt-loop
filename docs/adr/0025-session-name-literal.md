# 会话名＝人工指派的成品字面量：废 `<bot>-<machine>` 拼装公式，每轮照抄、禁现场拼装

## 背景

ADR-0015 决定 1 把会话名定为 `<bot>-<machine>` 拼装公式，slug 来源写死调用方
配置（DS Bot 用 bot 名；Grok Bot 用账号/配置名＋角色），但**成品名字仍要调用方
每轮现场拼装**。grill 2026-11-27 实证：拼 `--target` 的是调用方 LLM 每轮读
SKILL.md 现场发挥，没有固定配置字段可照抄，两侧调用方台账都出现同一派发实例
先后用多个名字的漂移（实证泛化，沿用 ADR-0010/0015 隐私先例，不录台账原值）：

- 任务级名字（按任务描述拟名，回到 ADR-0015 之前的老路）；
- 裸 t 号（绕过名字复用，且通知投影 `target` 继承 t 号、回传腿跟着漂）；
- 公式自由度连 machine 段都没锁住：有把 t 号当 machine slug 拼进去的
  （`<族>-<t号>` 式），有把 hostname 拼进去的（`<族>-<hostname>` 式）。

get-or-create（ADR-0009）只按 `--target` 字面值命中：名字漂移即静默另建会话，
同一实例累积多条命名会话，正是 ADR-0015 要消灭的症状从公式自由度里复发。

事实核查（grill 2026-11-27，用户确认＋仓库核对）：

1. 漂移全在**新任务派发腿**（调用方自拟 target 一侧）；回传腿照抄通知投影
   `target`（`docs/relay-routine.md` 定稿纪律），本身不漂移、只继承派发腿的错名。
2. DS Bot 每个 Bot 有平台分配的稳定 id（`session-<uuid>` 式，不可被任务改写），
   但**bot 名可随时改、且允许重名**（现有两个 Bot 共用同一名字）——ADR-0015
   「DS Bot 用 bot 名」有改名即漂移、重名即互撞（`session_occupied`/`not_idle`）
   的隐患；平台 id 超 32 位，截断后唯一性靠自律。存在恒加载、任务提示词改不动
   的配置面：**Bot 的 instructions**。派发的会话落本机。
3. Grok Bot（远端机）有对等写死面：**单 routine 固定文本**（每次唤醒必加载、
   任务提示词改不动）。其 SKILL.md 运行副本已含 ADR-0015 整节——「漂移是副本
   落后于旧约定」的假设被否掉，漂移发生在约定已加载的前提下。
4. 名字按机器解析、两机不共享（ADR-0015 背景 1）；dispatch 创建路径无跨机
   创建（无 `--on`）。故同字面量在两机＝两条独立会话，永不撞名；machine 段
   在名字里不承担跨机路由职责。另有机器看不见自己的 herdr 机器名（`hc ls`
   machines 为 None），machine 段无论哪种读法都得人工写死。
5. 调用方前提（用户确认）：**一个 bot 只对应一台机器**；同实例同机串行
   （ADR-0015 决定 2）不变。

## 决定

（grill Q1–Q11 裁定，2026-11-27；纯约定＋文档，零 dispatch.py 改动、零新 error
kind、零 result 字段变更、零退出码变更。）

1. **会话名＝人工指派的成品字面量**（supersede ADR-0015 决定 1 的形态段＋来源
   句）：不再规定 `<bot>-<machine>` 或任何结构。指派纪律：可读、**全局唯一**、
   一经写死永不改、指派时即满足 1–32 位 `a-z0-9-_`（指派时约束，不是运行时
   截断）；只能人工指派，不从 bot 名（可改可重名）或平台 id（超长）派生。
   字面量写进该派发实例的**恒加载配置**（DS Bot 的 instructions／Grok Bot 的
   唤醒 routine 固定文本），**每轮照抄、禁止现场拼装**——禁借任务名、t 号、
   hostname 等任何运行时值拼名。已稳定运行的既有字面量直接追认（如
   `loopeng-local`，结构不再被规定、只是历史成品）。
2. **一派发实例恒一条**：跨仓库、跨 kind；同实例同机串行由调用方保证（ADR-0015
   决定 2 语义不变，「一 bot 一机器」是调用方前提）。机械安全网：名字按机器
   解析、跨机创建不支持（背景 4），即使前提哪天破了，同字面量在两机也只是
   两条独立会话，不撞。
3. **约定内禁裸 t 号**：常规派发必须传会话名（照抄自己配置里的成品字面量）；
   裸 t 号仅限约定外逃生门／人工调试。不删 `--target` 收 t 号的能力、不加机械
   闸。回传腿照抄通知投影 `target` 的纪律不变（派发腿正确则回传腿天然正确）。
4. **改名＝换实例**：字面量永不改；真要换名＝新字面量＋旧会话按 ADR-0015
   决定 9 自然结束。存量漂移会话不迁移（沿用决定 9：在跑的自然结束，idle 的
   用户手动关 tab，不为改名 kill）。
5. **指派表私有**：哪个实例→哪个字面量由用户维护，不进公开仓库。把字面量
   写进各调用方恒加载配置（含重名实例逐个指派区分字面量）属**部署侧**动作，
   另开部署票跟踪，不在本 ADR 实现范围（沿用 #64 先例）。
6. **脚本零改动**：零映射、只校验 1–32 位 `a-z0-9-_`、不校验式样；违约机械
   兜底（`not_idle`、`session_occupied`、`reset_required`）全部沿用既有。
7. **词汇**：GLOSSARY「会话名」条目重写为成品字面量定义；不新增词条（成品
   字面量是会话名的赋值纪律，不是新实体）。

## Considered Options

- **B：dispatch 支持 target 默认值／配置来源**：否——违反「herdr 模板退居调用方
  持久配置仓库，loop 不感知模板、不自建配置文件」（ADR-0009），且只能给默认值，
  拦不住调用方主动传错。
- **C：会话名式样机械校验／新 error kind**：否——拦不住语义错名（任务级名字
  同样符合式样），且需重开 ADR-0015 的零代码约束。
- **machine 段视角澄清（a 本机相对调用方／b herdr 机器名）**：否——用户裁定
  整段删除：一个 bot 只对应一台机器、名字只在同机解析，同机唯一就够；字面量
  人工指派时保证唯一，machine 在名字里不承担机械职责。
- **保留公式＋加强纪律**：否——根因正是公式留了运行时自由度，实证连 machine
  段该填什么都没锁住；成品字面量把自由度归零。
- **A 不是机械零漂移（如实接受）**：写死字面量后仍要过调用方 LLM 才发出
  `--target`，只是把自由度从「公式＋自由发挥」压到「照抄一个词」。残余漂移
  风险接受，不加机械闸。

## Consequences

- 调用方配置固定项三→二：成品会话名字面量、常驻空间。machine slug 规则退役。
- 约定无机械强制，靠调用方读新 SKILL.md＋恒加载配置里的字面量生效；部署副本
  落后仍是已知风险面（ADR-0015 Consequences），四份运行副本同步属部署侧。
- 部署侧注意：Grok Bot 唤醒例程定稿文本（`docs/relay-routine.md`）有「逐字、
  不再改写」约束，写入字面量属对定稿文本的修订，需重新过审核／字数口径，不在
  本轮仓库侧改动里静默发生。
- 已接受的代价：残余 LLM 照抄漂移风险（无机械兜底）；全局唯一靠指派自律，
  脚本只校验字符集与长度。
- 零 dispatch.py 改动、零新 error kind、零 result 字段变更、零退出码变更。
- 隐私：公开仓库不出现真实机器名、hostname、用户名、绝对路径；漂移实证泛化；
  指派表私有（决定 5）。
