# next_skill＝抽取顺便做的下一步 skill 预测

> 2026-11-25 修订（#48）：原决定的 `next_command`（完整斜杠指令＋参数）改为 `next_skill`（纯 skill 名），参数归还调用方；预测可见性作为第一阶段先行。机械反馈、近期 skill 序列与在线 few-shot 由 ADR-0012 接续。文件名保留原 slug，避免既有链接失效。

## 背景

PAW 系调用方有时把该走 skill 的活用纯文本直令发进执行者会话，绕过打法 skill 的触发与重置纪律。ADR-0008 原方案复用抽取的同一次模型调用，从执行者回复预测下一轮完整斜杠指令，以零新增调用、零发送路径改动提供下一步建议。

#48 的 grill 重新裁定：抽取器没有调用方的完整上下文，票号、任务名等参数预测代价高且容易猜错；打法链高度线性，下一步使用哪个 skill 更容易预测，也更值得优化。因此预测收缩为 skill 名，参数由调用方根据完整上下文自填。

## 决定

1. **字段**：`next_skill`（字符串）＝调用方下一轮应使用的 skill 名，不带斜杠、不含参数；`""`＝无预测。候选集固定为七项：`wayfinder`、`grill-with-docs`、`to-spec`、`to-tickets`、`implement`、`implement-spec`、`prototype`。不从历史自动扩集；扩集须另行明确决策并同步 prompt、文档与测试。
2. **调用方拼指令**：非空预测由调用方拼成 `/<next_skill> <参数>`，参数完全由调用方填写。主任务放行文件首个非空行仍是实际 `/skill 参数` 或普通任务文本，不插入预测状态标签。
3. **唯一推测字段**：extract.md「只依据原文，不推测」规则为 `next_skill` 保留显式例外；其余字段逐字纪律不动。`next_skill` 豁免原文子串校验，不进 `rewritten`。
4. **闭集宽容投影**：缺失、非字符串、带斜杠、带参数或集外值均对外投影为 `""`，不整轮报错，形状门不检查它。学习阶段另记 `invalid_prediction`，不得把格式错误算作正确弃答。
5. **预测可见性硬纪律**：每轮放行卡固定展示上一轮同 target 的预测 skill，并标四态之一：
   - `照用预测`：沿用同一 skill，调用方自填参数不算编辑；
   - `已编辑：<理由>`：改用了不同 skill，理由必写；
   - `上轮无预测`：上一轮 `next_skill=""`；
   - `预测不可得`：没有可取得的上一轮同 target 结果，不猜测、不补造。
   状态标签只给用户看，不写进主任务提示词文件。取回结果后，选项卡另标「本轮新预测 skill」，不得与「上轮预测」混写。
6. **建议不是闸**：不碰发送路径、无新 error kind、不拒发、不强制改写放行。预测是会话起始 skill 且 `turn > 0` 时，同次放行仍按 ADR-0004 推荐 `--reset`。
7. **两后端同生效**：api/pi 共用 extract.md；两处字段指令同步修改。直接以 `next_skill` 替换 `next_command`，不保留兼容双字段。
8. **两阶段交付**：第一阶段只交付字段瘦身、闭集校验、可见性纪律、测试与文档，不引入持久学习存储，完成时不关闭 #48；第二阶段交付 ADR-0012 的反馈与学习机制后才关票。

## 被否方案

- **完整指令 `next_command`**：参数缺少调用方完整上下文，猜错成本高；字段瘦身为纯 skill 名，旧字段不留兼容别名。
- **参数命中率／完整一致率／历史参数复用**：随完整指令预测整片作废；历史真实标识符也不作为当前参数来源。
- **pre-send 识别闸**：每轮增加模型调用与发送故障面，误拦风险高；本决定继续维持建议性。
- **纯机械关键词表预测**：越过「脚本做机械、模型做语义」边界，词表维护不尽且误伤正常中途指令。
- **裸 skill 名但不呈报**：调用方不可见就无法形成及时纠正；可见性必须先于学习机制落地。

## 后果

- result/webhook 的第六字段由 `next_command` 改为 `next_skill`；旧调用方须适配新字段并自行组参。
- 预测质量指标只剩 skill 命中率、预测覆盖率与空预测正确率，不再评估参数。
- 「呈出预测＋照用作开场＋偏离明示理由」是调用方硬纪律，但不是机械发送闸。
- 第一阶段刻意不等待学习系统，先让用户看见每轮照用或纠正；第二阶段才积累可复算反馈并反哺预测。
