# 折叠判据实证替换与降级为标记

## 背景

issue #79 实证：一轮长活（6m53s，含两次 commit 与完整 code-review）在目标会话里已彻底
做完，dispatch 却返回 `incomplete_result`——回复散文里引用了一次折叠判据，那两个箭头
字符（U+25B2/U+25BC）出现在正文里，命中纯子串判据。误报代价是整轮结构化结果全丢：
不抽取、不出 result、`next_skill` 与学习结算都不发生。

只读调查实证（2026-11-25，hc/herdr 0.1.22，claude code 2.1.331）：

- **hc/herdr 不画任何标记**：herdr-core 二进制与上游源码全仓 0 处 U+25B2/U+25BC；
  `stitch.rs` 明文「The rows themselves are never changed」，拼接只做 trim_end＋join，
  不注入任何标记。折叠指示符只能是目标 TUI 自己渲染的。
- **那两个箭头字符无折叠语义**：claude code 二进制里是表格字形/Mermaid 箭头/选择器
  指示；qwen code 里是行首滚动指示（若改采「行首箭头」收窄，目标换 qwen 反成新误报源）。
  执行机回读语料里它们只出现在正文中（含判据自身的引用），从不出现在 TUI 折叠位置。
- **旧判据开火 6 次，全部误报、0 次真命中**。口径：`$TMPDIR/loop/runs/*.json` 台账
  （排除 `.result.json`/`.notify.json`）中 `complete_reason` 含 `fold_markers` 的条目，
  截至 2026-11-25 20:30 共 6 条，每条都返回 `error.kind=incomplete_result`，即每轮
  结构化结果整份丢弃：`grill50-r2-20261125-1152`(11:52)、
  `grill50-r3-20261125-1227`(12:27)、`tospec50-r1-20261125-1233`(12:33)、
  `tospec50-r2-20261125-1234`(12:34)、`issue61-impl4-20261125-1950`(19:50)、
  `issue79-grill-20261125-1945`(19:51)。6 份对应 `.raw.md` 都含 U+25B2/U+25BC，且
  无一处在 TUI 折叠位置（探针括注、正文里引用判据字面）。反例对照：
  `issue79-close-20261125-2000.raw.md` 含 30 处箭头但全在本轮段之外（被 turn cut
  截掉，同轮 `.turn.md` 0 处），故未开火——判据作用域是本轮段，不是整份回读。
- **claude code 真实折叠形态**（二进制模板＋真实语料双证）：行首 `… +N lines`
  （… 恒 U+2026，真实语料字节 e2 80 a6；可带 `(~K KB)` 后缀；模板有单复数变化）、
  `› Message from @X (ctrl+o to expand)`、
  `⎿ Backgrounded agent (↓ to manage · ctrl+o to expand)`。
  回读语料中该计数形态行首出现的共 111 处（69 份 `.raw.md`）；另有 26 处是正文引用
  该形态时的行内写法，不属 TUI 渲染，故不混计。
- 判据字符系 `df38c51`（2026-11-19）引入的未实证设计假设，引入时无实测样本。唯一
  真实折叠记录（#16 验收）是 grok「首行 + …」，也不是箭头。
- hc read 自报 `complete` 与折叠无关：截至 2026-11-25 20:30 带 `hc_read.complete` 的
  339 份台账**全部 true**（0 份 false），其中 94 份同轮 `.raw.md` 里就出现了折叠形态。
  方向「只在 hc 自报 complete=false 时硬阻断」再次被否（ADR-0013 已实证请求历史时
  complete 会恒变假）。语料总量随轮次增长（当次快照 317 份 `.raw.md`＋353 份台账），
  故上述条目只钉口径与条数，不把总量当常量。

## 决定

1. **判据替换**：删除那两个箭头字符（U+25B2/U+25BC）的纯子串判据，替换为两个独立
   命中分支——分支一：去前导空白后行首匹配 `… \+\d+ lines?\b`（… 恒 U+2026，不是三个
   ASCII 点）；分支二：行内含字面 `ctrl+o to expand`（不带左括号——⎿ 变体左括号后
   另有内容）。命中原因字符串沿用 `fold_markers`。
2. **降级为标记**：命中不再阻断——照常抽取、照常出 result，`complete:false`＋
   `complete_reason:["fold_markers"]` 供人复核；`incomplete_result` error kind 退役。
   与锚点降级（ADR-0013）同构：启发式不配硬闸；误报代价（丢整轮）远大于漏检代价
   （result 带标记）。
3. **回声排除**：本轮段里与本轮已知提示词某行（去首尾空白后）精确相同的行，退出折叠
   判据作用域——自己发出去的已知文本不是 TUI 渲染证据。`.turn.md` 与逐字校验语料
   不动（ADR-0013 决定 4 的逐字校验那半继续有效）。
4. **部分覆盖声明**：本 ADR 显式**部分 supersede ADR-0013 决定 4**：只覆盖「折叠判据
   是本轮段唯一硬闸」那半——判据字符替换为实证形态、命中由硬阻断降级为不完整标记；
   「逐字校验作用域＝本轮原料」那半**不受影响、继续有效**。ADR-0013 决定 1/2/3/5 不变。
5. **通知白名单扩展**：`NOTIFY_SUCCESS_FIELDS` 增 `complete`/`complete_reason`
   （11→13 字段），成功通知恒带完整性标记；error 通知不套白名单、照旧全量，回读后
   发生的错误（如抽取失败）也带完整性标记。此为对 ADR-0014 决定 2 的**增补**（非覆盖）。
6. **学习结算照旧**：结算、反馈、待观察创建照旧；仅标记轮的干净回复在结算入案例池时
   标 `learning_excluded:"incomplete_turn"`，不进 few-shot 注入（复用 `space_changed`
   先例机制）。反馈度量 next_skill 预测准不准，与折叠正交；截断回复是坏样本，污染会
   传播进后续抽取。旧 pending 记录无 complete 旗标按完整处理（向后兼容）。

**缺口声明**：判据只覆盖 claude code 2.1.331 实证形态。其他 kind（grok「首行 + …」、
qwen 等）与键位重映射场景的折叠可能漏检；不为未实证形态加猜测性判据，待该 kind 真实
折叠语料到手再按实证扩分支。同 ADR-0013 声明 1000 行上限的先例，如实声明而非静默假设。

## Considered Options

- **收窄箭头判据（行首/成对约束）**：字符本身无折叠语义，qwen 行首滚动指示反成新
  误报源，否。
- **hc 自报 complete 作闸**：ADR-0013 已实证不可靠（请求历史时恒变假），且与折叠
  无关，否。
- **泛化 `…` 判据覆盖 grok**：散文行尾省略号无处不在，必大量误报，否。
- **保留硬闸只收窄判据**：自指无解（本 ADR 自身就含判据字面），撞一次丢一轮，否。
- **标记轮跳过学习结算**：结算发生在发送时、早于回读，跳过须重构时序；反馈链断档
  会让下一轮失去结算对象，否。

## Consequences

- 误报代价从「丢整轮」降为「result 带标记待人复核」；漏检代价＝未标记的不完整
  result，不劣于现状（旧判据对真折叠本来就全漏）。
- `ok:true` 不再蕴含 `complete:true`：调用方契约变更。仓内无代码按 `incomplete_result`
  分支；仓外传话例程若写过该 kind 分支，退役后成死分支，须迁移到「ok:true 且
  complete:false → 复核」。通知字段是增补，不破坏现有读取。
- 残余自指如实声明：本 ADR 与 REFERENCE 自身含分支二字面，讨论它们的轮次可能命中
  标记——这正是降级吸收的残余，不再堆护栏。旧箭头字符在文档中一律写码位
  （U+25B2/U+25BC），不写字面。
- 回声排除的两个已知残余：回声首行带 ❯ 前缀、超宽行被 pane 软换行拆碎，均不与提示词
  行精确相等，排除不到；由降级吸收。
