# 回读范围、断轮与校验语料：1000 行历史回读＋回声断轮＋本轮原料

> 补记（ADR-0019，#79）：**决定 1 的判据半句（「`fold_markers` 仍是唯一完整性硬闸」）
> 与决定 4 的折叠判据那半被部分覆盖**——判据字符（U+25B2/U+25BC）经实证无任何 TUI
> 折叠语义，替换为 claude 实证形态（行首 `… +N lines`／行内 `ctrl+o to expand`），
> 命中由硬阻断降级为 `complete:false` 标记，`incomplete_result` 退役；回声行退出判据
> 作用域。决定 1 的「回读 1000 行」那半与「逐字校验作用域＝本轮原料」不受影响。详见
> ADR-0019。

> 补记（#127）：抽取器输入另附本轮发送提示词作回声参照，参照不是校验语料（#68）。

## 背景

issue #50 实证：一轮长任务（约 28 分钟）完成后，调用方收到的 `extraction_rewritten`
错误提示在句子中间断掉——错误载荷把含最接近原文片段的 JSON 整体硬切到 300 字符，
切在字符串内部，既不能解析也不能读。根因有三：

1. 错误载荷硬切 300 字符（`verify_extraction` 对 `json.dumps(rewritten)` 切片）。
2. 只抓当前屏（裁定 A3，`READ_LINES = 0`）：长回复远超一屏，抓到的只有尾部，
   开头从半句开始（已滚走）；`complete` 判据只看 `▲▼` 折叠标记，不覆盖「滚出屏幕」，
   长回复照样判 `complete: true`。
3. 错误文案写死「pi 在改写而不是抽取」，但该轮 `extract_backend: "api"`，误导排障。

hc 0.1.22 只读实测（本机，未碰生产会话）：

- 全屏 TUI 的拼接历史（stitched）**最多 1000 行**；历史可能包含此前多轮对话。
- working 状态下请求历史仍可能只返回当前屏；hc 自报 `complete` 会随请求历史而变为假。
  故 `complete` 不能解释为 agent 是否结束，也不能作完整性硬判据。
- **证据边界**：原裁定 A3 所称「grok 请求历史时 complete 恒 false」本次**未复现**，
  但缺少具备长历史或 working 状态的 grok 只读场景，不能宣称已全面证伪。采用新方案
  的依据是当前可验证的回读行为、断轮与校验作用域，而不是对 grok 历史行为的过度断言。

## 决定

回读范围、断轮、双产物与校验作用域是一组联动决策：

1. **回读 1000 行**：`READ_LINES` 由 0 调至 **1000**（hc stitched 历史上限），请求最近
   1000 行拼接历史＋当前屏，不再只抓当前屏。不新增任何启发式硬判据，`fold_markers`
   仍是唯一完整性硬闸；hc 自报 `complete`/`how`/`why` 只作台账元信息。**超过 1000 行
   历史的回复开头仍不可得**——回读全文不等于无限完整历史，在 SKILL.md/REFERENCE.md
   如实声明；「以 raw 文件为准」的循环论证措辞作废。
2. **回声断轮**（确定性机械步，不用模型）：锚点仍是主任务提示词第一个非空行前 24
   字符（不足取整行），匹配沿用字面＋去空白折叠容错。在回读全文中取「去前导空白后
   以 `❯` 开头且含锚点」的**最后一行**往后切到末尾——回复正文引用锚点但无 `❯` 前缀
   时不会误切回复开头；无 `❯` 形态回声时退化为含锚点的最后一行；锚点完全找不到则
   整段使用（诊断不因断轮失败再丢失）。选中的回声行保留在段内。
3. **双产物**：`<id>.raw.md`＝回读全文逐字落盘（审计，含被切掉旧轮）；`<id>.turn.md`
   ＝本轮段逐字落盘（抽取器输入＋逐字校验语料）。两者都不改字、不补字、不做行内截断。
   result `raw_record` 仍指全文，新增 `turn_record` 指本轮段，`run_record` 仍指干净全文；
   台账记 `echo_found`、`turn_cut_line`（1 起切点）、`turn_chars`（段字符数），整段使用
   时 `echo_found:false`、切点 1、字符数＝全文。
4. **校验作用域＝本轮原料**：折叠判据 `▲▼` 与逐字校验（`verify_extraction`/`verify_reply`）
   都只对本轮段；最接近原文片段也只从本轮段非空行选。旧轮折叠不误报本轮；整段使用时
   旧轮折叠仍可命中，此时阻断是诚实的。`anchor_found` 维持信息字段、不阻断。api 与 pi
   两后端都读本轮原料；`prompts/extract.md` 补「只摘最新一轮、逐字复制不许改写」。
5. **可读错误载荷**：`extraction_rewritten` 不新增结构化字段；hints 每个未过校验字段
   一条「字段名＋最接近的原文整行」（零截断），另给本轮段路径＋回读全文路径；不再对
   序列化 JSON 切片。message 按实际后端（api|pi）取值。其余五处纯文本 stderr/stdout
   摘录的 300 字符噪声护栏**不动**。不新增 error kind、不改退出码、不阻断主轮。

本 ADR **显式 supersede 裁定 A3**（issue #16，「只取当前屏；grok --lines > 0 时
complete 恒 false」）。A3 仅作历史注释保留；REFERENCE.md 机械节与 `dispatch.py`
回读常量旁注释同批指向本 ADR。

**与 ADR-0005 的关系**（显式标注，domain.md「Flag ADR conflicts」）：本 ADR 改写
ADR-0005 决定 2/7 记录的抽取输入语料——「整屏原文」→「本轮原料」（api 内联、pi
@文件 都改附本轮段）；ADR-0005 的运输层（协议、env、错误映射、零回显、parse_extraction
契约）不变，已在其标题下加补记指向本 ADR。与 ADR-0002「脚本干机械活、抽取器干抽取」
一致：断轮是新增的确定性机械步，仍归脚本。

## Considered Options

- **维持只抓当前屏（A3）**：长回复开头滚走、干净全文从半句开始却判 complete，否。
- **启发式完整性判据**（「从句子中间开始」「回复明显过短」）：误报硬阻断，违背降级
  哲学，否（Out of Scope）。
- **模型判轮次边界**：不确定、新增模型请求，断轮用确定性回声匹配即可，否。
- **自动滚动/按键/补发补齐历史**：碰 hc keys、违背只读护栏，否（Out of Scope）。
- **错误载荷加结构化 `rewritten` 字段**：改错误契约、调用方需迁移，否；hints 逐字段
  整行已可读可解析。
- **解除 hc 1000 行上限**：改 hc/herdr 本身，超出本票，否（Out of Scope）。

## Consequences

- 长回复（超一屏）能完整取回，抽取与逐字校验只作用本轮段；旧轮文本不能替改写蒙混。
- 抽取失败错误载荷可解析、不出现切开的结构；message 与实际后端一致。
- 残余缺口如实声明：超 1000 行历史的开头不可得；working 态回读可能仍只当前屏。
- 词汇表「整屏原料」改名「回读原料」，新增「断轮」「本轮原料」，与抽取器「裁剪」分名；
  「干净回复全文」名保留、定义改诚实版本。
- grok 历史行为证据不足处不宣称证伪；未来修改回读策略以本 ADR 实测依据为起点。
